Centcom docs

Everything you need to run, configure and trust Centcom. Pages marked Planned describe features that are designed and contracted but not built yet.

Overview

Centcom is a terminal and web app for coding agents. It starts the Claude Code or Codex you already have installed, turns their output into one consistent interface, and puts every edit and command behind an approval you control. A pixel octopus called Cento shows what the agent is doing.

  • Your login stays yours. Centcom never reads, stores or sends credentials. It runs your CLI and asks it for its status.
  • Two front ends, one agent. A full-screen terminal app and a local web app that can open as an app window.
  • Built for teams later. LAN and hosted multiplayer are designed in public contracts; they are Planned.

Early development. Centcom runs from source today. There is no packaged installer, and some parts of the plan are not built. See Status.

Install

You need Node.js 22 or newer, pnpm, git, and at least one agent CLI that is installed and signed in: claude (Claude Code) or codex (Codex). Linux is the tested platform.

git clone git@github.com:Caffeine-Driven-LLC/Centcom.git
cd Centcom
pnpm install

Check what Centcom can see:

pnpm centcom provider status

It prints whether each CLI is installed and whether it reports being signed in. If a CLI is missing, install it from its vendor and sign in the way its documentation describes.

Quick start

Try the demo (no login, no model)

pnpm dev

A scripted agent plays a realistic session. Type /demo fix, /demo search or /demo delete and press y or n at the approval cards.

Use your real agent in the terminal

Centcom works in the folder you start it from, so run it from your project. Until there is a packaged installer, the simplest setup is an alias that points at your clone:

# add to ~/.bashrc or ~/.zshrc, adjusting the path
alias centcom='/path/to/Centcom/node_modules/.bin/tsx /path/to/Centcom/apps/cli/src/main.tsx'

cd ~/your-project
centcom                    # Claude Code
centcom --engine codex     # Codex

Use the web app

pnpm web         # opens http://127.0.0.1:58008 with the launcher
pnpm web:app     # same, as a chromeless app window

Pick a folder, choose Claude Code or Codex, then Start on web or Start as app.

Terminal app

The layout adapts to your terminal size. At 120 columns and 34 rows or more you get the large Cento and the full transcript. A panel listing everyone in the session appears only when more than one person or agent has joined. Smaller windows get a small Cento, then none, and the minimum usable size is 60 by 14.

  • Transcript. Your messages, streamed replies with markdown, thinking summaries, and tool calls with results and diffs. It stays put when you scroll up and shows how many new lines arrived.
  • Live strip. Cento, the current activity, elapsed time and tokens.
  • Prompt. Multi-line input, history, paste, and a slash-command popup. End a line with \ and press Enter for a new line.
  • Status line. Permission mode, agent state, tokens, estimated cost and your 5-hour limit when the provider reports it.
  • Appearance. Graphite (dark) and Paper (light) themes; truecolor, 256, 16 or no color (NO_COLOR is honored); reduced motion.

Web and desktop app

pnpm web starts a local server on 127.0.0.1:58008 and opens the launcher. The launcher shows whether Claude Code and Codex are installed and signed in, lets you browse to a project folder or pick a recent one, and offers two ways to start:

  • Start on web opens the workspace in the current browser tab.
  • Start as app opens a window with no tabs or address bar, using its own browser profile at ~/.centcom/app-profile. It needs Chrome, Chromium, Brave or Edge. A packaged desktop app is on the plan.

Both views show the same running agent. Close the workspace with the back arrow; the agent session ends.

The workspace

  • A composer with the model menu, permission-mode menu and auto-skills toggle built in.
  • Tool cards you can expand, with a spinner while running and a tag when waiting for you.
  • An approval card with the exact command or diff, and the same Allow, Always this session and Decline choices as the terminal.
  • A side panel with your Cento and its state; when others join it also lists everyone in the session. Hide it with ctrl+b.
  • A status bar with the context window, your session and weekly limits (with time until they reset), tokens, estimated cost, model and permission mode.
  • A command palette (ctrl+k) for every command, model, mode and setting, a shortcuts screen (?), the Cento animation gallery (/cento), and a dark, light or system theme.
  • Every slash command works in the browser exactly as in the terminal.

The server only accepts connections to 127.0.0.1 and localhost on its own port, checks the Host and Origin headers, and requires a secret token. See Security. If port 58008 is taken, set CENTCOM_PORT.

Models

Press ctrl+o, use /model, or open the model menu in the web composer. A change applies from your next message; a running turn keeps its model. /model <id> accepts any model id your CLI understands.

Claude Code and Codex

Claude Code

Centcom runs claude -p with streaming JSON output and resumes the same session between messages. Approvals are bridged with a small local tool passed through --permission-prompt-tool (see Security). Sign in with claude auth login.

Codex

Centcom starts codex app-server and talks JSON-RPC over stdio. Streaming text, reasoning, shell commands, file changes, usage and rate limits all map onto the same interface, and file and command approvals go through the same dialog. Sign in with codex login.

Codex status. The Codex adapter is built against Codex's published protocol schema and passes its tests against a protocol-faithful stand-in and the real handshake. It has not yet completed a real model turn, because no signed-in Codex account was available during development. If your login has expired you will see "Codex is not signed in, or the login has expired"; run codex login.

Choosing the agent

pnpm centcom --engine claude-code   # default
pnpm centcom --engine codex

In the web launcher use the Claude Code / Codex switch. If neither CLI is installed, Centcom falls back to the demo agent and says so.

Permissions

PlanRead-only; writes are declined without a prompt.planon-request + read-only
Skip permissionsNever ask. See below.bypassPermissionsnever + danger-full-access

Change mode with shift+tab, /mode, or the web mode menu. Ask first is passed to Claude explicitly. Otherwise your own Claude settings, such as defaultMode: auto, could silently approve things.

Risk labels

Commands are classified low (read-only like ls, git status), medium (most things) or high (rm -rf, sudo, force-push, curl | sh, git reset --hard, and similar). Unknown commands are medium. High-risk approvals need a second confirmation in the terminal and can never be set to "always".

Always this session

Choosing a remembers the same tool and command or path for the rest of the session. It is never offered for high-risk actions.

Dangerously skip permissions

This turns off every approval. Cento will run commands and edit files immediately, including destructive ones. Use it in a sandbox, a container or a throwaway checkout, not on work you cannot recover.

pnpm centcom --dangerously-skip-permissions     # alias: --yolo
# or inside the app
/mode bypass          # aliases: yolo, skip, dangerous

In the web app open the mode menu, choose Dangerously skip permissions, and confirm. While it is on you get a warning in the transcript, a red banner across the top of the web workspace, a red composer and a ⚠ NO APPROVALS status in the terminal. Switch back with /mode default, shift+tab (one press leaves it) or the banner's button.

In the terminal, shift+tab only cycles into this mode if you started with the flag; otherwise you must type the command on purpose.

Auto skills

Before each message is sent, Centcom scores your installed skills and commands against it, locally and without calling a model. It applies the best one to three and shows what it picked and why. Your message appears exactly as you typed it.

  • Where skills come from: ~/.claude/skills, installed plugins, the project's .claude/skills and .claude/commands, and the bundled centcom-master library.
  • Control: /auto on|off, the Auto skills toggle in the web composer, and /skills [filter] to list. /skills enable <id> and /skills disable <id> turn bundled skills on or off.

centcom-master

A curated library of design, backend, security and workflow skills, exposed as one router skill plus an index so the agent never loads them all. Fetch it with:

pnpm skills:sync

It clones the source repositories listed in packages/skills/catalog.tsv into ~/.centcom/master, keeps text files only (scripts are left out), pins each skill to a commit, and scans for prompt-injection and obfuscation. Skills from publishers outside the trusted list, skills that need hooks or an MCP server, and overlapping alternates are off by default. Anything the scanner blocks stays quarantined until you enable it by hand.

The skill descriptions come from third parties. Centcom treats them as data, scans them, and never runs bundled scripts. Read a skill before you enable one you do not recognize.

Security and privacy

  • No credentials. Centcom never reads or stores your Claude or Codex login. It asks the CLI for status and passes your environment through unchanged.
  • Approval bridge (Claude Code). Centcom creates a private temporary folder (mode 0700) with a Unix socket and a config for a tiny MCP tool. Claude calls that tool when it needs permission; the tool forwards the question to Centcom over the socket. If Centcom cannot be reached, the answer is deny. The folder is deleted when the session ends.
  • Web server. Binds to 127.0.0.1 only. Rejects any Host other than 127.0.0.1:PORT or localhost:PORT (so DNS-rebinding fails), requires a secret cookie, checks the WebSocket Origin, serves a strict Content-Security-Policy and never serves files outside its own build folder. The token lives in ~/.centcom/token with mode 0600.
  • Redaction. Error text from the CLIs is passed through a redactor that removes key-like strings before it is shown.
  • Bundled skills. Text only, scanned, pinned, and off by default unless from a trusted publisher.
  • Telemetry. None today.

Multiplayer will add end-to-end encryption (XChaCha20-Poly1305 with Ed25519 and X25519 keys) so a hosted relay only sees ciphertext and a small set of routing metadata. Planned

Who pays

Model usage is billed to the provider account that signed in to the CLI that made the call. Centcom does not resell, meter or proxy model usage. The costs Centcom shows are estimates from the CLI's own reports.

For multiplayer, the planned rule is simple: a person's agent runs on that person's own account. Sharing one subscription across a team is a question for your provider's terms; Centcom will default to blocking subscription-backed engines in shared command posts until that is confirmed in writing.

Multiplayer and teams Planned

Designed and contracted, not built yet:

  • LAN mode (free). Machines on the same Wi-Fi discover each other, pair with a short code, and share one session. No account, no server. The host approves; everyone sees one transcript.
  • Hosted relay (paid). The same experience from anywhere, with accounts, workspaces, roles, invites, history, notifications and an audit log. The relay routes ciphertext and cannot read your code or prompts.
  • Fleet. Parallel agents in isolated git worktrees with file locks and a board showing who needs you.

The wire formats, error codes and entitlements are frozen in the public contracts/ folder of both repositories, so the client and server can be built independently.

Architecture

The client is a TypeScript pnpm monorepo. Packages depend in one direction only.

PackageRole
@centcom/themeColor tokens and terminal color tiers
@centcom/mascotCento sprite engine, scenes, state driver, 319 baked animations
@centcom/agentThe AgentEngine interface and normalised events; Claude Code, Codex and demo engines; approval bridge; risk classifier
@centcom/skillsSkill discovery, matching and the centcom-master library
@centcom/tuiInk components and the controller shared by both front ends
apps/cliThe centcom command
apps/webLocal server and React web client

Every engine produces the same event stream (text.delta, tool.requested, approval.requested, tool.result, usage.report, limits.report, turn.done and so on). The controller turns events into state; the terminal and web UIs only render state. That is why both behave the same.

The client and the backend are built separately and meet only at the versioned contracts/, locked by CONTRACTS.lock and identical in both repositories.

Troubleshooting

"Codex is not signed in, or the login has expired"

codex login status only checks that credentials exist. If the stored token can no longer refresh, Codex's server reports no account. Run codex login again.

"Claude Code was not found"

Install Claude Code and make sure claude is on your PATH, then run claude auth login. Until then Centcom shows the demo agent.

Ask first is not asking

Update Centcom: it now passes --permission-mode manual explicitly. Older builds inherited your own Claude default mode.

The web app says it is starting forever

Update and restart the server. An older build cleared its state when the workspace opened and only recovered if the agent was busy.

Port 58008 is in use

Centcom is probably already running; open the printed URL. Otherwise set CENTCOM_PORT.

"Start as app" opens a normal browser

No Chrome, Chromium, Brave or Edge was found. Install one, or use Start on web.

Strange characters in the terminal

Use a font with box-drawing and block characters, such as a Nerd Font. Try --colors 256 if colors look wrong, or --mascot off in tiny windows.

Skills are not applied

Run /skills to see what was found and /auto on to make sure matching is enabled. Run pnpm skills:sync once to fetch the bundled library.

Contributing

The work is split into 100+ independent lanes per side, each with a goal, contracts, acceptance criteria and tests. Start with plan/START_HERE.md in either repository, pick a lane from the "Ready to pick up" list in the README, and update plan/STATUS.json when you finish or advance one. Run pnpm typecheck && pnpm test before opening a pull request.
